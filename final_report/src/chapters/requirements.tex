\section{Software Requirements}
The implementation relies on a specialized ecosystem of Python libraries designed for memory-efficient training and standardized benchmarking.

\subsection{Programming Language:}
\begin{itemize}
    \item \textbf{Python 3.8+} is the primary programming language, chosen for its extensive support in machine learning and data science libraries.
\end{itemize}

\subsection{Frameworks and Libraries:}
\begin{itemize}
    \item \textbf{Numpy \& Pandas:} For efficient data manipulation and preprocessing, used to handle prompts, predictions, and evaluation metrics.
    \item \textbf{BitsAndBytes:} Provides 4-bit Quantization (NF4) and Double Quantization, enabling the model to fit in limited GPU memory. Used for memory-efficient loading of LLaMA-2-7B with LoRA adapters.
    \item \textbf{Transformers \& TRL:} Hugging Face libraries for loading, tokenizing, and generating code using pre-trained language models. The \texttt{Trainer} API is used to manage fine-tuning loops.
    \item \textbf{Optuna:} Hyperparameter optimization framework using TPE (Tree-structured Parzen Estimator) to automatically search for optimal learning rate, LoRA alpha, dropout, and other tuning parameters.
    \item \textbf{peft:} Implements Parameter-Efficient Fine-Tuning techniques like LoRA adapters, reducing trainable parameters while allowing effective adaptation of large language models.
    \item \textbf{datasets:} Provides easy access to standard datasets such as \texttt{human\_eval}, enabling straightforward integration with PyTorch for evaluation of model performance.
    \item \textbf{PyTorch:} Deep learning framework used for model training, GPU acceleration, automatic differentiation, and managing tensor operations during fine-tuning and evaluation.
    \item \textbf{human\_eval:} Benchmark dataset for evaluating code generation models on functional correctness. Used to compute pass@k metrics in this project.
    \item \textbf{tqdm:} Provides progress bars for loops, used to visually track dataset iteration and code generation evaluation progress.
    \item \textbf{matplotlib:} Python plotting library used to visualize training metrics, validation loss, and evaluation results for the fine-tuned model.
    \item \textbf{codebleu:} Metric to evaluate code generation quality considering syntax, data-flow, and n-gram similarity. Used to assess functional and structural correctness of generated code.
    \item \textbf{sacrebleu:} Standardized BLEU score computation used to evaluate code similarity and translation quality for generated solutions.
\end{itemize}

\subsection{Development Environment:}
\begin{itemize}
    \item \textbf{Hugging Face Hub:}
    A centralized platform for sharing and accessing pre-trained models and datasets.
    \item \textbf{Google Collab:}
    Provides access to high-performance GPUs for fine-tuning and evaluation.
    \item \textbf{Kaggle CLI:}
    Used for data preparation and hyperparameter optimization, leveraging Kaggle's GPU resources.
    \item \textbf{Weights \& Biases (W\&B):} 
    Used for real-time telemetry, monitoring validation loss curves, and logging hardware consumption across all 45 HPO trials.
    \item \textbf{Git \& Github:}
    Version control and collaborative development platform for code management and documentation.
    \item \textbf{LaTeX (Overleaf):}
    Used for writing the final report, ensuring professional formatting and presentation of results.
\end{itemize}

\subsection{Data Collection:}
\begin{itemize}
    \item \textbf{Hugging Face Datasets:}
    A library for accessing and processing a wide variety of datasets, including those relevant to code generation tasks.
\end{itemize}


\section{Feasibility Analysis}
This project is primarily targeted at fine-tuning large language models for Python code generation using Parameter Efficient Fine-Tuning (PEFT) with QLoRA. The feasibility of this project is analyzed from the following perspectives:

\subsection{Schedule Feasibility}
The project is scheduled into three phases including data collection,model-fine tuning, and evaluation.With the completion of evaluation before the final stage the project successfully well-aligned with the academic calendar.

\subsection{Operational Feasibility}
The project is designed to be applicable on relatively low-end devices. The hardware requirement for Llama-2 7B is approximately 6-8GB of VRAM, which is widely available in consumer-grade GPUs such as the NVIDIA RTX 3060 or 4060 and the Google Colab free tier (T4 GPU). 
The use of QLoRA significantly reduces the memory footprint, making it feasible to perform fine-tuning on a single consumer-grade GPU rather than requiring an enterprise-level server cluster.

\subsection{Economic Feasibility}
The project utilizes freely available open-source models (Llama-2) and public datasets (FlyTec, Alpaca). Since the hardware constraints are low enough to utilize existing consumer-grade GPUs or free cloud-based services like Google Colab, the primary development cost is minimal. 

\subsection{Technical Feasibility}
The implementation relies on well-established, industry-standard libraries such as Hugging Face \texttt{transformers}, \texttt{peft}, and \texttt{bitsandbytes}. These libraries provide robust support for 4-bit quantization and LoRA adapter integration. The team possesses the necessary proficiency in Python programming and machine learning frameworks to manage the model loading, data preprocessing, and evaluation pipelines effectively.

\subsection{Legal Feasibility}
The project adheres to all relevant legal and ethical guidelines. The use of open-source models and datasets ensures compliance with licensing agreements. Additionally, the project does not involve any personally identifiable information (PII) or sensitive data, mitigating potential privacy concerns. All code and documentation will be shared under an appropriate open-source license to promote transparency and collaboration within the research community.
